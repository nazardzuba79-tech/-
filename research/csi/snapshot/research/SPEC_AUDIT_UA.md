# Аудит вкладених вимог — зберегти контракт, не приховати суперечності

1. **Обсяг.** Текст повідомлення просить 100–200 у кожній групі, вкладення — приблизно 100. Обрано 120+120. Вони не означають 240 незалежних predictors. Три композити не будувалися.
2. **Режим.** Mode B фактично встановлений code-runtime preflight. У режимі B схема порожньої БД збережена для сумісності, але це не зібраний dataset. `lag_check` не може пройти емпіричну перевірку без рядків.
3. **Lag contract.** Збережені точні 0/1/8/30 днів. Це задані припущення користувача, не підтверджені дати кожного релізу. [FRED API real-time periods](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html) пояснює revised-vs-vintage; не називати fixed lag достатнім доказом no leakage.
4. **Daily lag 0.** День може бути відомий лише після закриття; модель має окремо задати час рішення. Date-only схема не зберігає intraday timestamp. Збережіть точні API timestamps у raw і додатковий release ledger без зміни заданих core-таблиць.
5. **Funding.** У вкладенні написано «сума 3 виплат». [USD-M futures market data API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data) дозволяє adjustment fundingIntervalHours. Сумувати фактичні події, не створювати відсутні дві/три. У `funding_event_counts` явно фіксувати кількість; сама кількість не доводить completeness. Це відкрита корекція припущення, не мовчазна зміна канонічного імені.
6. **OI history.** Документація обмежує відповідний endpoint останнім місяцем. Не поширювати цей висновок на всі можливі архіви всіх бірж, але не стверджувати довгу історію без отриманих файлів. Не підміняти OI funding-ом.
7. **Time semantics OI.** У документації timestamp позначає кінець періоду. Перед парсингом 1d визначити, який UTC-день описується. Не використовувати naive date(timestamp) без перевірки boundaries.
8. **Coin Metrics.** Наявність MetricID в official index не доводить Community entitlement або applicability btc/eth. Зібрати actual catalog і desired-minus-obtained. Запасний api.coinmetrics.io не вважати автоматично безключовим. Exact API catalog pagination теж перевірити.
9. **Активи.** HashRate/DiffMean не є еквівалентними post-Merge ETH staking. Не зберігати відсутність PoW як справжні нульові спостереження. Canonical requested pair усе одно залишається у missing report з причиною.
10. **Units.** WALCL, WTREGEN, WRESBAL — millions; RRPONTSYD та M2SL — billions у відповідних FRED описах. Net liquidity heuristic вимагає scale conversion; WTREGEN weekly average не той самий sampling, що WALCL Wednesday level. Нічого не інтерполювати в core-series.
11. **DXY.** DTWEXBGS — broad trade-weighted dollar, не ICE DXY. У каталозі вони різні поля. DXY залишено untestable без перевіреного feed.
12. **Stablecoins.** Ключ `peggedUSD` може бути вкладений у різні об’єкти. Перед map totalCirculating vs totalCirculatingUSD перевірити одиниці фактичного response; не сумувати позначення того самого supply двічі.
13. **Форвардний bias складу.** Для top100 потрібні історичні constituents та delistings. CoinGecko price history не вирішує цю вимогу сама. Не міняти days=max на коротку історію так, щоб створити враження повного збору.
14. **Farside.** Web-read succeeded, runtime fetch не виконувався після глобального DNS gate. Це не «Farside HTTP 403». Повну історію ETH не підтверджено. Після реального блокування не використовувати інше ETF-джерело всупереч вкладеному ТЗ.
15. **Source substitutions.** Лише дозволені запасні джерела й те саме канонічне ім’я за ідентичного економічного визначення. Якщо визначення інше — інший id/metric. За успіху primary запасний ряд у series не додавати.
16. **Pine.** [Pine Script — Other timeframes and data](https://www.tradingview.com/pine-script-docs/concepts/other-timeframes-and-data/): довільний API pipeline не дорівнює Pine feed; нові Pine Seeds repositories недоступні. Повна Python система та reduced Pine не однакові моделі.
17. **Джерела без повного читання.** У registry є explicit open-failed, prior-conversation та shell-only записи. Для RHODL, Reserve Risk, деяких adjusted/cohort variants немає перевіреної повної специфікації. Не перетворювати операційний опис на нібито точну копію провайдера.
18. **Обмеження схеми vintage.** Primary key з date не зберігає декілька revisions одного спостереження. Raw append-only і fetch timestamps зберігають отримані версії. Для справжнього PIT-тесту потрібні історично доступні vintages або явне застереження; додати sidecar, не змінюючи canonical schema без погодження.
