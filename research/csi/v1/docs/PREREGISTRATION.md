# Pre-registration: CYCLE / REGIME / TACTICAL (v1)

Зафіксовано **до** обчислення будь-якого IC або backtest. Хеш реєстру ознак із напрямками:
`csi/features.py` sha256 = див. `docs/PREREGISTRATION_HASH.txt` (записується автоматично скриптом `csi/evaluate.py`
при першому запуску та звіряється при кожному наступному; зміна файлу після першого запуску = порушення протоколу, яке
фіксується в `experiments/experiments.jsonl`).

## 1. Дані та ціна рішення
- Актив: BTC (первинний). ETH — тільки як перевірка стійкості напряму для ознак, що існують для ETH (не в цьому релізі).
- Ціна для цілей: **CYCLE** — Coin Metrics `PriceUSD` (референсна ціна кінця дня, 2010-07-18+), не виконувана ціна біржі;
  **REGIME** і **TACTICAL** — OKX spot `BTC-USDT` денний close (`1Dutc`, 2018-01-11+), lag 0. Серії не зшиваються.
- Момент рішення: закриття дня D (00:00 UTC дня D+1). Ознака використовується, лише якщо `available_at <= D`.
  Coin Metrics: `available_at = date+1`; FRED: +1/+8/+30 за контрактом; DefiLlama: +1; OKX bars: 0; OKX rubik-статистика: +1 (межі періоду не доведені).
- Останнє відоме значення переноситься не довше `max_stale` днів (7 daily; 10 FRED daily; 45 weekly; 60 monthly). Це інформаційна множина, не інтерполяція джерела.

## 2. Цілі
Forward log return `log(P[D+h]/P[D])`, h ∈ {1, 7, 30, 90, 180, 365}.
- CYCLE primary: h=365; secondary: 180.
- REGIME primary: h=30; secondary: 90.
- TACTICAL primary: h=7; secondary: 1.

## 3. Зрізи (точне операційне тлумачення)
`full`; `ex_2020-03_2022-01` (вилучено спостереження з D у [2020-03-01, 2022-01-31] **та** ті, чиє вікно [D, D+h] перетинає цей інтервал);
`ex_2017` (аналогічно для 2017-01-01..2017-12-31); `since_2022` (D >= 2022-01-01).

## 4. Розбиття в часі
- Development (train + walk-forward): усе до **2022-12-31** включно за датою рішення D, і тільки якщо D+h ≤ 2022-12-31.
- Embargo: 30 днів.
- **Final holdout (untouched)**: D ≥ **2023-01-31**, до останньої дати, для якої D+h існує. Відкривається один раз, після фіксації складу систем на development. Повторний прогін після перегляду holdout не вважається новим blind-тестом.
- Walk-forward у development: щорічні expanding folds: fit на даних до 31.12.(Y−1) з purge h днів, оцінка на рік Y; Y = 2015..2022 (CYCLE, CM-ціна), 2020..2022 (REGIME/TACTICAL, OKX-ціна з 2018; перша fold потребує ≥ 2 роки train).

## 5. Статистика
- Spearman IC на кожному горизонті/зрізі.
- Невизначеність: circular block bootstrap, довжина блоку `max(h, 20)`, 300 реплік, 90% інтервал. Ефективна вибірка ≈ N/h (звітується).
- Ранжування одиночних ознак — за **найгіршим валідним зрізом** при заздалегідь заданому знаку. Зріз валідний, якщо N ≥ 20·h/… точніше: N_eff = N/max(h,1) ≥ 30; інакше `insufficient`.
- Ознака "підтверджена на development", якщо на primary horizon: знак IC збігається з pre-registered у всіх валідних зрізах development **і** 90% bootstrap-інтервал pooled walk-forward IC не містить 0.

## 6. Правила побудови композитів (без оптимізації ваг)
- Компоненти-кандидати: лише зі списку `features.py` для відповідної системи, зі знаком ≠ 0.
- Нормалізація компонента: causal expanding percentile rank (min 365 днів історії) × pre-registered sign.
- Кластеризація на development: Spearman-кореляція між компонентами; пари з |ρ| > 0.8 = одна сім'я; з сім'ї береться одна ознака з кращим worst-slice development IC (правило, не пошук).
- Composite score = **рівнозважене** середнє нормованих компонентів (NaN ігноруються, потрібно ≥ 50% компонентів).
- Ablation: leave-one-out на development; компонент лишається, лише якщо його видалення НЕ покращує pooled WF IC більш ніж на 0.01 (тобто він не шкодить). Жодних інших переборів.
- Бюджет пошуку: один композит на систему + LOO-ablation + baselines. Усі спроби логуються в `experiments/experiments.jsonl` із лічильником.

## 7. Baselines для порівняння (усі при однаковому режимі виконання)
Buy-and-hold; price-only (CYCLE: Mayer Multiple; REGIME: SMA200 distance; TACTICAL: RSI14); onchain-only (CYCLE: MVRV; REGIME: exchange netflow); cash.

## 8. Витрати та виконання
Позиція змінюється на закритті дня D за ціною close(D) (припущення; фактичне виконання після 00:00 UTC). Комісія 0.10% + проковзування 0.05% = 0.15% на сторону, стягується на |Δpositions|.
Оцінка стратегії: score → експозиція (long-only, 0..1) без порогів: CYCLE exposure = 1 − pct_rank(score) (перебалансування щотижня); REGIME exposure = pct_rank(score) (щотижня); TACTICAL exposure = pct_rank(score) (щодня). Це risk gate/ sizing, не торговий сигнал шорту. Метрики: CAGR, vol, Sharpe, max drawdown, turnover, порівняно з baselines при тій самій середній експозиції (vol-matched Sharpe). 

## 9. Stopping rule
Після одного проходу development → фіксація складу → один прогін holdout → звіт. Негативний результат публікується як негативний. Ознаки з < 2 років історії (funding, OI, long/short, taker) звітуються як `insufficient evidence` і не входять до композитів.

## 10. Що НЕ робиться
Не підбираються пороги; не змінюються знаки; не використовується holdout для відбору; не заповнюються пропуски; не використовуються серії з підміненим означенням під канонічним ім'ям без окремого id.
