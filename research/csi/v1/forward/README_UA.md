# Журнал прямого (forward) тесту

Навіщо: історія вже переглянута, тому чесно перевірити індикатори можна лише на майбутніх даних. Щодня записується оцінка кожної
замороженої системи **до того**, як стане відомий результат.

- `frozen_specs.json` — склад систем (заморожено 2026-09-23). Не змінювати: зміна = нова система з новою назвою.
- `ledger.csv` — лише дописування. Кожен рядок містить хеш попереднього рядка і хеш коду; `python -m csi.forward verify` перевіряє, що нічого не переписано.
- Колонки `components_stale` / `source_last_observation` показують застарілі входи (наприклад, BitMEX закритий 2026-09-16, FRED H.10 виходить раз на тиждень).
- `ledger_discarded_init_2026-09-23.csv` — перша ініціалізація того ж дня, відкинута до першого коміту через помилку метаданих (дата панелі замість дати джерела). Оцінки в ній ті самі.
- Оцінка: `python -m csi.forward evaluate` — враховує лише рядки, записані не пізніше ніж через 2 дні після дати рішення.

Щоденне оновлення: `./update_all.sh` (дані → перевірки → dashboard → запис у журнал → перевірка хешів).
