# Індикатори для TradingView (безкоштовний план достатній)

Файли в `platform/pine/`. Статус усіх: **написані для Pine v6, не компілювалися автором** (у дослідницькому середовищі немає редактора TradingView).
Якщо редактор покаже помилку — скопіюйте текст помилки і рядок, я виправлю.

| Файл | Що показує | Символ графіка | Що втрачено проти Python-моделі |
|---|---|---|---|
| `CSI_Cycle_Gauge.pine` | «дорого/дешево» 0..100: Mayer, 2Y MA, 200W MA, power-law residual (єдиний компонент, що мав узгоджений напрям на 2011–2022) | денний BTC з довгою історією: `BITSTAMP:BTCUSD` або `INDEX:BTCUSD` | MVRV, Puell, thermocap, біржові баланси (немає в TV) |
| `CYCLE_reduced.pine` | те саме без power-law, простіша версія | так само | так само |
| `REGIME_reduced.pine` | тренд + волатильність + долар/реальна ставка (FRED) + ETH/BTC | `BINANCE:BTCUSDT` або `OKX:BTCUSDT` D | стейблкоїни, біржові потоки, net liquidity, ETF, активність мережі. **Python-версія REGIME на холдауті провалилась** — це лише огляд фону |
| `TACTICAL_reduced.pine` | розтягнутість: RSI, %B, stochastic, CCI, drawdown, basis перп/спот | `OKX:BTCUSDT` (basis бере `OKX:BTCUSDT.P`) | funding, long/short, taker. **Контртрендова гіпотеза не підтвердилась** — індикатор показує стан, не сигнал |

## Як додати
1. TradingView → внизу «Pine Editor» → «Open» → «New blank indicator». 2. Видалити вміст, вставити текст файлу. 3. «Add to chart». 4. Для сповіщень: «Create alert» → умова з індикатора.

## Важливо
- Percent-rank у Pine рахується у ковзному вікні 1500 днів (`ta.percentrank`), у Python — у розширюваному з початку історії. Тому значення відрізняються за побудовою; паритет не заявляється.
- Дата публікації FRED-серій у TradingView не дорівнює контрактному лагу 1/8/30 днів з дослідження.
- Жоден із цих індикаторів не має підтвердженої переваги на відкладеній історії (див. `systems/SUMMARY_UA.md`). Використовуйте як «термометр», не як кнопку «купити/продати».
