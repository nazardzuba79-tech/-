## 2. Середовище та ізоляція від production

- Весь прохід виконано проти **локального read-only fixture-сервера** (`scripts/qa-mobile-client-fixture.cjs`): він віддає зібраний `frontend/dist` і синтетичні відповіді API (довгий email `very.long.customer.email.address.for.layout.checks@example-mail-provider.com`, довге ім'я, великі/від'ємні числа — PnL −48 575 USDT, 98 765 432 109,87 PEPE, ціни 0,00001234, KYC «відхилено» з довгою причиною, помилкові/порожні стани).
- **Жодного запису**: будь-який не-GET запит сервер відхиляє з 405 і рахує (єдиний виняток — POST `/banking/calculate`, чиста проєкція калькулятора Earn, яку fixture рахує сам зі своєї таблиці програм і нічого не зберігає); у фінальному прогоні — `0` відхилених записів, `12` викликів калькулятора.
- **Жодного запиту назовні**: Playwright блокує всі не-локальні origin'и (у т.ч. `market.voltextech.net`, шрифти Google, аналітику), WebSocket-з'єднання закриваються одразу; локальна копія Inter підставляється замість fonts.googleapis.com. Production API, платіжні сервіси, Telegram, пошта недосяжні за конструкцією.
- Токен сесії для fixture підписується **випадковим секретом** процесу; production-акаунт не використовувався ні для чого.
- Збірки, скриншоти, відео — тільки локально в середовищі сесії; у репозиторій входять лише стиснені JPEG-пари «до/після», одне коротке відео та матриця.
- Runtime: Node `v22.22.0`, Playwright `1.56.1`, Chromium `1194` (headless, емуляція touch, DPR 2 для телефонів, DPR 1 для планшета/десктопа). **WebKit у середовищі не встановлено** — див. §7.

## 3. Карта перевірки

Маршрути й стани складені з коду (`App.tsx`, навігація, вкладки терміналів, умовні екрани). Повна матриця «маршрут → стан → ширина → результат» — у [matrix.md](matrix.md) (генерується з сирих вимірювань скриптом `scripts/qa-mobile-client-report.cjs`; компактні вердикти по комірках — [cells.json](cells.json)).

Ширини: 320×568, 320×740, 360×800, 375×812, 390×844, 412×915, 430×932 (телефони, touch), 844×390 (landscape), 768×1024 (планшет), 1366×768, 1440×900, 1920×1080 (десктоп-регресія). Основна мова проходу — російська; додатково — англійська, китайська, іспанська на 360/390 (§6) і прохід без локальних шрифтів (fallback до системного стека).

Стани на маршрут (усього `91` комбінацій, `1092` знімків у фінальному прогоні):

- `/` — перший екран, мобільне меню; `/login`, `/register` — порожня та заповнена форма (довгий email), 200% тексту; `/legal/terms`; `/academy`, `/academy/learn`, `/academy/faq` (+ відкрите питання), `/academy/glossary`; `/help/fees`.
- `/markets` — список, меню, пошук, підтримка; `/markets?view=analytics`.
- `/trade?pair=BTC/USDT` (Spot) — Торговля (купити; продати-ліміт з заповненими полями), График, стакан, список пар, Ордера (відкриті / історія / активи), депозит, 200% тексту; окремо пари PEPE (крихітні ціни) та VTA.
- `/trade?market=cfd` — Торговля, список інструментів, Позиции.
- `/futures` — ліміт-ордер з заповненими полями, графік, стакан, 24h-показники, позиції, діалог TP/SL, відкриті ордери, історія позицій, історія ордерів, активи, діалог закриття (ліміт і ринок з підтвердженням), вибір контракту, калькулятор, 200% тексту.
- `/wallet` — Финансирование, Unified Trading, P&L Analysis, Orders (історія операцій), діалоги Внести / Вывести (порожній і заповнений) / Перевести, 200% тексту.
- `/banking` (Earn) — перший екран, розрахунок, діалог розміщення; `/copy-trading` — профіль трейдера, його угоди; `/otc` — форма порожня/заповнена; `/arbitrage` — список, деталі стратегії; `/tools`; `/trading-bots` (+ бот); `/card`; `/settings` — безпека, верифікація (KYC відхилено), API-ключі, реферали; віджет підтримки на кожній сторінці.
- Наскрізний сценарій з відео (§8): ринки → термінал → форма ордера → Ордера → перемикач Spot/Фьючерсы → позиції → гаманець.

Stocks та інші неопубліковані функції у production не активувались; маршрутів з прапорцями, що їх вмикають, у fixture не ввімкнено (вони відображаються як у production — приховані).

Що міряє прохід на кожному стані: горизонтальна прокрутка сторінки (`scrollWidth` документа/`body`), блоки за правим краєм поза локальним скролером, текст, обрізаний без «…», накладання текстових рядків, елементи, накриті фіксованими шарами (через `elementFromPoint`) на першому екрані і в кінці сторінки, цілі тапу < 44×44 (окремо < 32), шрифти < 10px, `NaN/undefined` у тексті, помилки JS. Скриншот усієї сторінки та окремо нижнього екрана (після прокрутки в кінець).

## 7. Не перевірено

- **WebKit / Safari**: Playwright-WebKit у середовищі сесії не встановлено, встановлення потребує завантаження браузера з мережі. Емуляція WebKit і так не дорівнює реальному iPhone (safe-area, висота панелі адреси, клавіатура).
- **Реальні пристрої**, реальна екранна клавіатура, зміна висоти вікна при появі клавіатури (перевірено лише через `env(safe-area-inset-*)`/`dvh` у CSS і статичні вьюпорти).
- **Ландшафт** перевірено лише як 844×390 (один розмір).
- Hindi, японська, корейська — лише перевірка, що новий ключ є; повний прохід не виконано.
- Stocks та неопубліковані функції — не вмикались (лише перевірено, що вони не з'являються).
- Клієнти PWA/Telegram (`frontend/src/mobile-review`) — окремий продукт зі своїм CI, не входить у цей аудит.
- Адмін-панель — поза обсягом (інша гілка, див. §1).
- Доступність читачем екрана (VoiceOver/TalkBack) — не перевірялась, лише ролі/`aria`.
