# CFD information strip — sources, load budget, QA

Scope: the CFD terminal's ticker bar (`frontend/src/components/CfdTickerBar.tsx`) now carries the compact information strip: name → price → day change → day range → session status (→ 52‑week range and nearest release when applicable). Futures, Spot, the CFD order form, positions, trading maths and guards are untouched. No backend, Worker, database or deployment change.

## 1. Source audit, per field

Production reads only the Cloudflare edge (`https://market.voltextech.net/cfd/display/*?v=9`, 6‑hour snapshots). Development reads the same routes on Render (`/api/v1/cfd/display/*`, `publicDisplayCache`, 6 h). Instrument identity is the canonical catalogue symbol (`src/services/marketData/cfd/catalog.ts`, 13 rows: 4 metals, 2 energy, 7 FX majors; no index or stock CFD). Quote currency is the symbol's last three letters (`cfdQuoteCurrency`). All prices are the CFD display quote (provider mid or last), never an underlying exchange quote.

## 2. Load architecture (no new upstream path)

- Quotes: unchanged, the one existing 6‑hour ticker snapshot.
- Slow data (session, previous close, day range, optional 52‑week): **one** GET per viewed instrument, `GET /cfd/display/candles/<SYM>?interval=1d&limit=20` (+`&v=9` at the edge), through `readDisplayJson`: shared in‑flight promise per URL, in‑memory + localStorage cache keyed by URL, 6‑hour TTL honouring `max-age − Age`, 15 s abort, 60 s cooldown after a failure, `credentials: 'omit'`, `_display` envelope required. The hook `useCfdDailySession` aborts the request on instrument switch, keeps the last good series of the same instrument on error (retry after 60 s), clears its timer on unmount, pauses while the tab is inactive, and never touches the chart (no chart re‑creation; `CfdChart.tsx` is unchanged).
- Server: no new code. Render `publicDisplayCache` (6 h per URL, readers coalesced, negative cache 60 s, 64 entries / 8 MB) in front of `BiquoteCfdOhlcSource` (per‑key cache 15 s, one in‑flight request per key, 5 s timeout, 1.5 MB cap, `limit` floored at 20). Edge: Cache API 6 h per URL, same floor. Upstream cost per instrument: at most one daily‑series request per 6 h shared by every reader of that edge/Render cache. `src/cfd/__tests__/CfdDailySessionBudget.test.ts` pins: 25 simultaneous readers → 1 upstream request; the `1d&limit=20` key never collides with the chart's `1h&limit=320`; the 6‑hour display cache serves later readers without the source.
- Known limitation (pre‑existing, unchanged): the edge Worker does not coalesce two simultaneous cold misses of the same URL; two readers hitting an empty edge cache in the same second can cause two upstream requests, exactly as the chart today.
- Economic calendar (when a source is attached): the adapter is expected to cache per region for 60 min initially; nothing is fetched today.
- Browser: one subscription per mounted strip (one strip per page), no second WS/SSE, no polling increase, no per‑field requests, stale requests cancelled on switch, timers cleared, countdown local.

## 4. Before/after load, same fixture, same machine

Harness: a private Playwright script against the shared read‑only fixture (one express app serving the production bundle, `/api/v1/cfd/display/tickers` with four instruments, `/cfd/display/candles/:symbol` with an hourly series for the chart and a UTC‑day series for `interval=1d`). Chromium 1440×900, three runs per build, counts taken both in the browser (every `/api/v1/` response, body bytes) and at the fixture (requests actually served). "before" = the parity branch head e8a3245c without the strip; "after" = the same head plus the strip. All three runs of each build gave identical counts; bytes are the median.

| Scenario | Before (requests, bytes) | After (requests, bytes) | Delta |
|---|---|---|---|
| Cold open of the CFD page (empty storage) | tickers 1 (1.4 KB) · chart candles 1 (19.2 KB) · other API 3 (1.5 KB) | tickers 1 · chart candles 1 · **daily series 1 (3.2 KB)** · other API 3 | **+1 request, +3.2 KB** per cold instrument view |
| Four instrument switches (XAG → EUR → WTI → XAU) | chart candles 3 (57.5 KB) | chart candles 3 · **daily series 3 (9.7 KB)** | +1 request (~3.2 KB) per newly viewed instrument; a revisited instrument costs 0 |
| Tab hidden → visible inside the TTL | 0 market requests (1 unrelated API ping) | 0 market requests (1 unrelated API ping) | 0 |
| Warm reload (same browser storage) | 0 market requests (localStorage snapshot cache) | 0 market requests, daily series included | 0 |
| Three cold readers at once (separate storage, no server cache in the fixture) | per reader: tickers 1, chart 1 | per reader: tickers 1, chart 1, daily 1 | +1 per reader at the fixture; in production the edge/Render cache answers the second and later readers of an instrument from the same 6‑hour entry (`CfdDailySessionBudget.test.ts`) |
| JS heap after cold open | 10 MB | 10 MB | 0 |
| Four switches, wall time | 2.61–2.67 s | 2.62–2.66 s | within noise |

Upstream (provider) requests: not reachable from this harness (the fixture is the origin). Expected from the code and the budget test: at most one daily‑series request per instrument per 6 hours per cache tier, independent of the number of readers. Server CPU/RAM/event‑loop lag, p95/p99 at the origin and database reads: **INCONCLUSIVE / not applicable** — no server code changed and no origin load test was run (the brief forbids production load tests); the only new origin work is serving one more cached 3 KB JSON per instrument per 6 h.
