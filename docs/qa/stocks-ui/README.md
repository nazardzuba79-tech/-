# QA — Stocks panel and overview (PR #471 UI follow-up)

Local, isolated, **not production**. Every screenshot carries a red
"DEMO DATA · isolated QA fixtures, not market quotes" badge: prices and
candles are generated by `scripts/qa-stocks-ui-fixture.mjs`, not quotes.

## How it was run

- Built UI: `VITE_STOCKS_ENABLED=true VITE_STOCKS_ORIGIN=http://127.0.0.1:4431 npm run build --prefix frontend`.
- Crypto pages and the shared header use the read-only Express fixtures of
  `scripts/qa-spot-cfd-terminal.cjs`; writes are refused, outside hosts are blocked.
- Stocks reads the **real** read-only stock server (`services/stocks/server.mjs`,
  `Store` from `core.mjs`) over a disposable SQLite file: 250 catalogue rows,
  227 with candles (23 deliberately without data), 81,720 closed 15-minute
  candles placed only in each exchange's regular session (Tokyo, Hong Kong and
  Shanghai lunch breaks, DST), indices without volume, one sub-cent quote
  (`PINX:MGNT`). `sessionChange` stays `null`, as the server always returns it.
- `node scripts/qa-stocks-ui.cjs` → `report.json` here (245 checks, 0 failed,
  0 page errors, 0 writes; local run). Codex's `scripts/qa-stocks.cjs` (56 views) and
  `scripts/qa-stocks-navigation.cjs` (49 menu views, 5 Spot → Futures → CFD →
  Stocks → Spot runs with terminal style comparison) also pass on this build;
  only their selectors were updated to the new DOM.
- **CI:** since this revision `qa-stocks-ui.cjs` and `qa-stocks-navigation.cjs`
  run in the `stocks-ui-browser` job of `.github/workflows/stocks-review.yml`
  on the same fixtures (Playwright 1.56.1 Chromium, Node 24.21.0); its report
  and screenshots are the job artifact. Earlier "214 checks" were local only —
  no workflow ran them. `qa-stocks.cjs` (Vite dev server) is still local only.

## Data states (refresh failures and contract checks)

Both reads go through one hook (`frontend/src/lib/stocks.ts`) that keeps
"have data" and "state of the latest read" apart:

- An answer is checked against the contract of `services/stocks/server.mjs`
  before it can enter the cache: catalogue shape, canonical ids, OHLC order,
  15-minute candles in time order; a history page must carry the requested
  `instrumentId` (and currency) — except the server's own empty answer for a
  disabled instrument, `{"candles":[],"next":null}`, which is a valid
  «История пока недоступна». Another instrument's page, candles without an
  id, malformed JSON → an `invalid` error; the last valid page of *this*
  instrument stays.
- A failed refresh (HTTP error, 12 s timeout, invalid answer) keeps the last
  valid data on screen and adds a compact strip: «Не удалось обновить данные.
  Показаны последние полученные значения» (or «Получен некорректный ответ.
  Показаны последние корректные значения»), «Последняя свеча: …» from the
  data itself, and «Повторить». It stays until a read succeeds; a refresh in
  flight is not an error. The chart keeps its instance and zoom (pixel-equal
  before and after), no overlay covers it. Without earlier data the overlay
  says «Данные временно недоступны» / «Получен некорректный ответ. Данные не
  показаны» with a retry — never an endless spinner, never another
  instrument's candles.
- Applied to the panel chart, the instrument list (sidebar and drawer) and
  the overview. Market closure is never inferred from missing candles.
- Cadence unchanged: nothing is read inside the 15-minute window; at 15
  minutes one catalogue and one history read; a failed read is retried on
  the same 15-minute schedule or by «Повторить»; a manual retry joins a read
  in flight; a hidden tab reads nothing.

Browser checks on a controlled page clock (no real 15-minute waits), at 1440
and 390: cadence; successful same-instrument refresh keeps zoom and pixels;
refresh → 503 and → timeout keep the data with the warning; retry clicked
twice reads once; catalogue refresh failure keeps 250 rows in the list,
drawer and overview with the warning; hidden tab reads nothing for 45
minutes, one catalogue read when visible again; HTTP 200 with another
instrument's id → data error, no candles, no spinner; the same after a valid
AAPL page → AAPL kept with the warning, identical pixels after retry; valid
empty page → «История пока недоступна»; fast AAPL → MSFT → AAPL with a slow
MSFT answer → AAPL, one chart, identical pixels. Clicks right after a
fast-forward are dispatched to the element (a Playwright fake-clock input
quirk loses the first real click; real clicks are covered elsewhere).
