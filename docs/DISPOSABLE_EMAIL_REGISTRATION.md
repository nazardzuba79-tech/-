# Disposable email registration gate

Scope: only new account registration. Existing sign-in, existing sessions, balances and withdrawals remain untouched. Local normal (not strict/forwarding) upstream domain list, MIT notice in bundled snapshot; pinned upstream Git blob c4747b4cd6cb6e02f8fe732ab8dbfb19984e7059 (109341 entries). No additional packages. Known disposable domains and exact overrides are checked before account lookup or hashing. Common permanent mailbox providers are protected. Other legitimate providers remain allowed unless listed; false positives are possible and can be overridden.

The server refreshes the list once after startup and every 24h, outside the registration path, using the fixed upstream URL, timeout and size/format checks. A failed refresh retains the previous validated set. The snapshot is always available on a new instance. Set DISPOSABLE_EMAIL_CACHE_PATH to an API-owned persistent mounted file to keep the last validated update across container replacement. DISPOSABLE_EMAIL_ALLOW_DOMAINS and DISPOSABLE_EMAIL_BLOCK_DOMAINS accept comma-separated exact domains; no UI or per-attempt telemetry added in this narrow patch. Never send a submitted email to an external service.

Release: backend and frontend must both be built and tested. Verify backend refusal using an email-only request (no password, cannot create an account). Verify exact Russian text in real browser QA and all locale mappings. Use the currently deployed API and Pages base for separate narrow release candidates, not an unreviewed main deployment. Do not change existing account state, schema, deposits, trades or credentials. Configure persistent cache path explicitly before deployment. No deploy or merge in this candidate.
